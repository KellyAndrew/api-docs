Kyanite Overview

Welcome to KyaniteAPI. KyaniteAPI is an event ingestion and processing API that decouples client requests from downstream work. Clients submit events to KyaniteAPI, which validates and queues them for processing so your application can handle traffic spikes without blocking user interactions.

The Big Picture

Instead of writing directly to your primary database from the client, clients submit events to the ingestion endpoint. KyaniteAPI acknowledges accepted events with 202 Accepted and processes them asynchronously. This design helps you keep client interactions responsive while ensuring events are captured for downstream processing.

Core Features

Schema Validation: Validates incoming payloads against your configured JSON Schemas before accepting the event for processing.

Asynchronous Ingestion: Returns 202 Accepted after an event is accepted, so client requests remain fast and non-blocking.

Queued Processing: Events are placed onto a queue for downstream processing and delivery.

If you do have retries, retention, ordering, or delivery guarantees, state them explicitly (for example: “at-least-once delivery”, “retained for 24 hours”, “best-effort ordering per key”). Otherwise keep it as above.
